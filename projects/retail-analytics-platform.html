Project Overview

An end to end data analytics project built on real world retail store operations. The platform takes raw transactional and supply chain events through a normalised relational architecture into business intelligence dashboards, designed to deliver actionable insight into sales trends, product margins, customer payment behaviour and inventory stockout risk.

The transactional records are simulated with realistic retail demand patterns, so the whole pipeline can be built, tested and repeated safely. The project is in progress, with dashboards as the next phase.

Core Architecture & Tech Stack

  • Database and data modelling: PostgreSQL with a 3NF normalised schema, designed with explicit primary and foreign keys, check constraints and performance indexes.
  • Data engineering and simulation: Python with SQLAlchemy, pandas and Faker pipelines and seeds multi month transactional records, simulates realistic retail demand patterns and automates data ingestion.
  • Database administration: DBeaver for schema deployment, query execution, indexing optimisation and execution plan analysis.
  • Business intelligence (next phase): Power BI or Tableau connected directly through the PostgreSQL connector, to build executive and operational dashboards.

Key Competencies

  • Relational database design: structuring retail data across basket headers and line items while enforcing referential integrity and data constraints.
  • Advanced analytical SQL: aggregations, multi table joins, Common Table Expressions (CTEs) and window functions such as RANK(), LAG() and rolling averages, used to answer core business questions.
  • Operational retail metrics: basket size, average order value (AOV), revenue by payment channel (cash, card and MBWay), gross margin per SKU and safety stock threshold breaches.
  • Data pipelines and integration: bridging Python scripting with a production grade SQL database to ingest, clean and manipulate tabular datasets.
  • Executive storytelling: translating raw database queries into visual reporting that guides purchasing schedules, stock replenishment and promotion strategies.

Next Phase

The next step is to connect Power BI or Tableau to the PostgreSQL database and build executive and operational dashboards on top of the analytical queries, so that purchasing, replenishment and promotion decisions can be made from the visuals directly.
